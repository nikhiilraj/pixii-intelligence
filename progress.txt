## Codebase Patterns

### What this is

A standalone content-intelligence application that will replace `pixii-cli`,
`podcast-chopper`, `social-automation` and `ai-slop-scorer` (~30k LOC in
`~/monte-workshop/bots-and-tools/`). V1 is one vertical slice: Zernio corpus in → template
library → generate with lineage → Zernio draft → analytics joined back → dashboard.

Full spec: `.scratch/v1/spec.md`. Verified integration contracts: `.scratch/v1/seams.md`.
**Read both before the first slice.** They contain live-verified API behaviour that is not
guessable from documentation.

### Hard rules

- **Never write to `~/monte-workshop`.** Read-only reference only. This is a standing rule.
- **Nothing auto-publishes.** Every post reaches Zernio as a draft. This is permanent design,
  not a V1 limitation.
- **`.env` is a symlink to `~/Nikhil-workshop/.env`** — one source of truth. Never commit it,
  never write secret values into any file, never print a key value into logs or output.
- **Pin Python 3.12.** The system default `python3` is 3.14.0 and will be picked up silently.
- **Ponytail is on.** Laziest thing that works. No speculative abstractions, no interface with
  one implementation, no config for a value that never changes. Mark deliberate
  simplifications with a `ponytail:` comment naming the ceiling and the upgrade path.

### Stack

Backend: Python 3.12, FastAPI, Pydantic v2, SQLModel over SQLAlchemy, Alembic.
Frontend: Next.js 15 App Router, TypeScript, Tailwind, shadcn/ui, Recharts.
Database: PostgreSQL via Docker Compose (daemon confirmed running 2026-07-29).
Scheduling: APScheduler in-process. No Redis, no Celery, no broker in V1.
Package management: `uv` for Python, `pnpm` for Node. Both confirmed installed.

### The Zernio API — verified live 2026-07-29, do not re-derive

Base `https://getlate.dev/api/v1`, bearer auth with `ZERNIO_API_KEY`.
Zernio is the GetLate rebrand; `docs.getlate.dev` 301s to `docs.zernio.com`.

**`GET /v1/analytics` — two silent failure modes. Both return HTTP 200 with an empty list:**

- `limit` caps at **50**. `limit=200` returns zero posts and no `pagination` object.
- A `fromDate`/`toDate` span beyond **90 days** returns zero posts.

Page with `limit=50` and an incrementing `page`. **Treat an unexpected empty result as a
failure, never as an empty account.** The previous tooling carries a stale comment claiming
this endpoint does not exist at all; that class of silent, undetectable wrongness is exactly
what these tests guard against.

Per-post fields: `_id`, `latePostId`, `content`, `publishedAt`, `scheduledFor`, `status`,
`platform`, `platformPostUrl`, `mediaItems`, `thumbnailUrl`, `mediaType`, `profileId`,
`isExternal`, `isAd`, and `analytics{impressions, reach, likes, comments, shares, saves,
clicks, views, follows, engagementRate, lastUpdated}`. The `platforms[]` array repeats metrics
per account and carries `platformPostId` (`urn:li:share:…`) and `syncStatus`.

**`POST /v1/posts`** accepts `content`, `title`, `mediaItems`, `platforms`, `scheduledFor`,
`publishNow`, `isDraft`, `timezone`, `tags`, `hashtags`, `mentions`, **`metadata` (arbitrary
object — this is where lineage goes)**, and an optional `x-request-id` header for idempotency.
Returns `post._id`. **Draft is the default** when none of `scheduledFor`, `publishNow` or
`queuedFromProfile` is given. `POST /v1/posts/{id}/metadata` patches metadata later.

**Unresolved, and US-010 must resolve it:** the analytics payload carries both `_id` and
`latePostId` with different values. Which one the create response's `_id` corresponds to is
unknown and only determinable by creating a real post. Record the answer here when found.

### Corpus facts

50 posts available: 27 LinkedIn (Monte Desai), 13 YouTube (pixii.creates), 10 X (Pixii_ai),
spanning 2026-04-30 → 2026-07-28. 25 of 27 LinkedIn posts carry media. Average LinkedIn post
is ~818 characters. All 50 are `isExternal: true, syncStatus: "synced"`, so posts written
outside the app are included.

LinkedIn impressions, sorted: 6691, 5747, 4698, 3823, 2840, 1209, 1094, 928, 855, 800, 772,
640, 545, 525, 468, 457, 430, 405, 402, 394, 377, 354, 348, 332, 332, 111, 0.
Median 525, max 6691 — a **12.7x spread**.

**Primary success metric is engaged actions = likes + comments + shares + saves.** Not
impressions (the 6691 post drew 11 reactions), not engagement rate (a 332-impression post
scores 3.01). The two alternatives disagree on 60% of the top five.

**This is why V1 is a scoreboard, not an optimizer.** ~3 samples per template against a 12.7x
noise floor cannot support ranking. Show aggregates with their sample counts, flag thin
samples, let a human promote or retire. Do not build automatic template selection.

### Brand

Post visuals are 1080×1350 (4:5). Cream background `#F5F0E8`, heavy black type, orange Pixii
wordmark bottom-right. The established layout is an oversized ghosted figure behind a subject
image with a bold two-line headline beneath. Reference images from the real corpus are useful
for authoring visual templates — they are downloadable from `media.zernio.com` URLs in the
analytics payload.

Visual templates declare `renderer: "html" | "ai"`. Typographic frames use `html` because
image models garble large embedded text. Scene and lifestyle imagery uses `ai`.

### Missing corpus inputs — do not block on these

The creator posts Monte sent over LinkedIn, and the per-post design specifications, are not
in any repository or API. Extraction runs on the 27 available LinkedIn posts. Manual corpus
ingest exists so both can be absorbed later. **No slice's acceptance criteria may depend on
material that does not yet exist.**

### US-001 — Walking skeleton (done 2026-07-29)

Built by the orchestrator rather than a loop iteration: it scaffolds two toolchains and is
the least tracer-bullet-shaped slice in the list.

Delivered: FastAPI backend on 8000 with `/health` reporting database reachability and
credential presence (presence only, never values); Postgres 17 in Docker on **port 5433**
(not 5432 — avoids collision with the Homebrew postgresql@16/@17 installs on this machine);
Alembic wired with baseline `c2756fd0ca1a`; Next.js 15 + Tailwind 4 frontend on 3000 whose

runs everything.

Verified live end to end: `/health` returned `database: true` with all four credential groups
present, and the rendered page showed six green rows and no red.

Learned:
- `.env` is a symlink to `~/Nikhil-workshop/.env` and loads correctly through
  pydantic-settings from the repo root. Do not copy secrets into this repo.
- `uv venv --python 3.12` pins correctly; the machine default `python3` is 3.14.0.
- Alembic 1.14 needs `path_separator` in alembic.ini; the older `version_path_separator`
  spelling is deprecated.
- `create-next-app` produces Tailwind **4**, which has no `tailwind.config.ts` — configuration
  lives in CSS via `@import "tailwindcss"`. Do not add a v3-style config file.
- FastAPI's TestClient warns that `httpx` is deprecated in favour of `httpx2`. Harmless today;

- Compose uses `restart: unless-stopped` so a Docker Desktop restart does not silently kill
  long unattended runs.

### US-002 — Corpus ingest from Zernio (done 2026-07-29)

Delivered: `app/zernio.py` (paging client, `ZernioResponseError`), `app/models/post.py`,
`app/corpus.py` (`ingest_posts` upsert), `GET /posts` and `POST /corpus/ingest`, migration
`b3784bcd19d0`, and a `/posts` page ranking the corpus by engaged actions.

18 tests green, ruff and mypy clean. Verified live against the real API: first ingest
created 50, second created 0 and updated 50. Top of the ranking reproduces the corpus
exactly — 185, 139, 48, 26, 20 — and the 6691-impression post with 11 reactions correctly
does not appear in the top five, which is the whole point of the metric choice.

Learned:
- **The empty-response guard keys on the missing `pagination` object**, not on a zero-length
  post list. A genuinely empty account still returns `pagination`; a rejected request does
  not. That distinction is what makes the failure detectable at all.
- Alembic's `script.py.mako` needed `from sqlalchemy.dialects import postgresql` added —
  autogenerate emits `postgresql.JSONB` for JSONB columns but does not import it, so the
  first migration with a JSON column fails with `NameError`. The template is now patched, so
  later migrations inherit the fix.
- Ruff's `B008` fires on FastAPI's `Depends()` in argument defaults. Resolved with
  `SessionDep = Annotated[Session, Depends(get_session)]` — the modern FastAPI idiom, and it
  satisfies the rule rather than suppressing it. **Reuse `SessionDep` for new endpoints.**
- Tests use a transaction-rollback `session` fixture (`tests/conftest.py`) against the
  migrated database, and `app.dependency_overrides[get_session]` to give the API that same
  session. Remember to clear the override at the end of an API test.
- httpx `MockTransport` is how the Zernio client is tested without a network call. Follow
  this pattern for the Azure and Cloudflare adapters.

### US-003 — Media download and post detail view (done 2026-07-29)

Delivered: `app/media.py` (`download_post_media`), `local_media_path` on Post (migration
`3ea8ff85c496`), media served from `/media` via StaticFiles, `GET /posts/{id}`, and a
`/posts/[id]` detail page with a metrics grid, the media, and the full body. The corpus list
now links through to it.

28 tests green, whole gate clean. Verified live: 40 media files / 31 MB downloaded — which
matches the corpus exactly, since 10 of the 50 posts are text-only (24 image + 16 video + 10
text). `/media/<file>` served the 2,497,633-byte hero PNG at HTTP 200.

Learned:
- **Media download is opt-in via `ingest_posts(..., with_media=True)`.** Tests and
  metric-only refreshes stay offline by default; only the API route asks for media.
- Every media failure is logged and swallowed, returning None. A post is complete without
  its image, and losing an image must never cost the post.
- **The `session` fixture now truncates all tables inside its rolled-back transaction.**
  A live ingest commits 50 real rows, and tests that count the table were seeing them
  (`assert 62 == 12`). Truncate-then-rollback gives a clean slate without deleting real data.
  Any new test that counts rows relies on this.
- Alembic autogenerate emits `op.add_column` on one long line that trips ruff's E501. Wrap
  the generated call by hand; it is the routine cost of a new column.
- `next/image` is wrong for backend-served media at arbitrary paths — use a plain `<img>`
  with an eslint-disable directly above the tag. A disable comment separated from the tag by
  another comment line does not apply and becomes an "unused directive" warning.
- When checking rendered HTML, `grep -c` counts *lines* and Next.js emits one long line.
  Use `grep -o ... | wc -l` or the count is misleadingly 1.

### US-004 — Template library: model, versioning, lifecycle, editor (done 2026-07-29)

Delivered: `app/models/template.py` (one table, `kind` discriminator, JSONB body),
`app/templates.py` (create / edit / approve / retire / `latest_versions` /
`usable_templates`), `app/api_templates.py` router, `app/deps.py`, migration `4cdc7e782318`,
and a `/templates` page with an author-and-revise form plus approve/retire actions. Added
nav across all pages.

46 tests green, whole gate clean. Lifecycle verified live end to end: proposed → 0 usable;
approve → 1 usable; edit → v2 with v1 intact; retire → 0 usable; editing a retired template
→ HTTP 409; both versions still on record.

**Decisions worth knowing before building on this:**
- **`family_id` is the stable identity, not `id`.** Every version is its own row sharing a
  `family_id`. Performance attribution must key on `(family_id, version)` — never on `id`
  alone, or an edit silently detaches history.
- **An edited version inherits the status it was edited from.** A strategist editing an
  approved template in the UI *is* the approver, so demanding re-approval is friction
  without review. Extraction proposals still require explicit approval — that is where the
  "nothing unvetted" rule actually bites.
- **Retired templates are immutable** (`RetiredTemplateError` → 409). Author a new family
  instead of reviving one.
- `usable_templates(kind)` is the only thing generation may consume: newest version,
  approved, right kind. Use it rather than querying Template directly.

Learned:
- `SessionDep` now lives in `app/deps.py` so routers can share it. **Import it from there**,
  not from `app.main` — that would be a circular import.
- New routers go in `app/api_*.py` as an `APIRouter` and are included from `main`.
- Alembic writes enum columns on one long line that trips E501; wrap by hand, same as
  `add_column`.
- Checking rendered React output for a string built from an interpolation (`from {n} posts`)
  fails on a naive grep — SSR splits it with `<!-- -->` markers. Strip comments and tags
  before asserting on rendered text.

### US-005 — Hook extraction from the winning posts (done 2026-07-29)

Delivered: `app/llm.py` (`AzureChat` + an `LLM` Protocol), `app/extraction.py`
(`propose_hooks`), `POST /templates/extract/hooks`, `get_llm`/`LLMDep` in `app/deps.py`,
and an extract button on `/templates`.

65 tests green, whole gate clean. Run live against Monte's real 27 LinkedIn posts: **6 hook
templates proposed, 0 hallucinated provenance ids, 0 usable until approved.**

The proposals independently reconstructed the top three posts —
`ai-time-value-equation` (#1, 185 engaged), `dated-platform-countdown` (#2, 139),
`small-input-big-recurring-result` (#3, 48) — and found two patterns spanning *multiple*
posts (`headline-stat-reframe` from #6 and #9, `open-question-then-tested` from #7 and #12).
That cross-post generalisation is the signal that the ranking is doing real work.

Learned:
- **The `LLM` Protocol is the seam.** Anything with `complete_json(system, user) -> dict`
  satisfies it. Tests inject a plain stub; `AzureChat` itself is tested separately with
  httpx `MockTransport`. Reuse this shape for the image adapter.
- **`max_completion_tokens`, never `max_tokens`** — this deployment rejects the old
  parameter. Already in the seam notes; now enforced by a test.
- Models sometimes fence their JSON in ```json despite instructions. `_parse_json` strips
  the fence; unparseable output raises `LLMResponseError` rather than returning empty.
- **Provenance is filtered against the ids actually shown to the model.** An id the model
  invented is dropped rather than stored — provenance must stay checkable, and a
  hallucinated citation is worse than none.
- **Route order matters:** `/templates/extract/hooks` is declared before
  `/templates/{template_id}/approve`, or FastAPI tries to parse "extract" as an int and 422s.
- Inject external clients as FastAPI dependencies (`LLMDep`), not by constructing them
  inside the handler — otherwise the endpoint cannot be tested without a network call.

### US-006 — Post structures for offer-reward and deep-research (done 2026-07-29)

Delivered: `propose_structures` and `compatible_hooks` in `app/extraction.py`,
`POST /templates/extract/structures` (with `sample_size` and `focus`),
`GET /templates/{id}/compatible-hooks`, and an extract-structures button.

78 tests green, whole gate clean. Approved and live: **`ai-workflow-giveaway`
(offer-reward, 8 sections)** paired with `ai-time-value-equation`, and **`case-study-loop`
(deep-research, 6 sections)** paired with `small-input-big-recurring-result`.

**The finding that shaped this slice — worth carrying forward.** Extraction at the default
sample refused to produce a deep-research structure, twice. Not a bug: the corpus does not
contain a deep-research post that performed. Of 27 LinkedIn posts, 4 are research-shaped and
three of those rank #14, #20 and #26 — below the top-12 cutoff (engaged 11). Only rank #5
made the sample. **Ranking by engaged actions structurally hides post types that
underperform**, which is correct for "what works" and wrong for "cover this post type".
Hence `focus`: it names a type to describe and tells the model to say when the evidence is
thin. Use it whenever a wanted post type is absent from the default sample — and read the
absence as signal, not as failure.

Learned:
- **Cited names are resolved to `family_id` and unknown names are dropped**, exactly as
  provenance ids are. A structure pointing at an invented hook would break generation the
  first time anyone selected it.
- `compatible_hooks()` returns only *usable* hooks, so an unapproved or retired pairing
  silently disappears rather than offering something generation would reject.
- Structure extraction sends **whole posts** (`POST_CHARS = 2000`); hook extraction sends
  only the opening (`HOOK_CHARS = 220`). Different questions need different windows.
- `GET /{id}/compatible-hooks` 400s on a non-structure rather than returning an empty list —
  an empty list would read as "no pairings" instead of "wrong kind of thing".

### US-007 — Visual templates with the html renderer (done 2026-07-29)

Delivered: `app/rendering.py` (`fill`, `CloudflareRenderer`, `render_visual`),
`get_html_renderer`/`HtmlRendererDep`, `POST /templates/{id}/preview` returning image/png,
a preview button on `/templates`, and a real `stat-hero` template reproducing the brand
layout (cream field, ghosted figure, orange cross, bold headline, Pixii mark).

90 tests green, whole gate clean. Verified live: 1080x1350 PNG at HTTP 200; missing slot
422; non-visual template 400; an `ai`-renderer template 501 (dispatch follows the
declaration); an escaped `<script>` value rendered as visible text with the layout intact.

**Decisions worth knowing before building on this:**
- **Visual templates carry their HTML as data, not a component name.** The spec sketch said
  "component identifier"; a markup string in `body.html` is lazier and strictly better here —
  a new visual template needs no code and no deploy, it versions like any other template,
  and a designer can edit the CSS directly in the editor.
- **`str.format()` cannot be used to fill slots.** CSS is full of braces —
  `.card { color: red }` — and format() chokes on them. `fill()` does targeted replacement
  and then scans for leftovers with a deliberately narrow `{snake_name}` pattern.
- **Slot values are escaped; template chrome is trusted.** That is the trust boundary:
  chrome is authored by the team, values will come from a language model.
- **A leftover placeholder raises rather than rendering.** Shipping an image with a literal
  `{headline}` in it is worse than failing.

Learned:
- **Cloudflare Browser Rendering rate-limits (429) under rapid successive calls.** It first
  surfaced as an opaque 500; the preview route now maps upstream `httpx.HTTPStatusError` to
  502 naming the upstream status, so "rate limited, retry" is distinguishable from "broken".
  **Later slices that render in a loop must pace themselves or handle 429.**
- The preview UI fills slots from each slot's own `example`, so a preview shows what the
  template author considered representative rather than lorem text.

### US-008 — Visual templates with the ai renderer (done 2026-07-29)

Delivered: `AzureImageRenderer` and an `ImageRenderer` protocol in `app/rendering.py`,
dispatch in `render_visual`, `get_image_renderer`/`ImageRendererDep`, and Pillow for scaling.
`.scratch/v1/seams.md` updated — the image seam is now verified rather than assumed.

102 tests green, whole gate clean. Generated live through the app: a 1080x1350 product shot
on the brand cream, no text — exactly the case the ai path exists for.

**The contract, verified live — this was the one seam never exercised:**
- `POST {endpoint}/openai/deployments/gpt-image-2/images/generations?api-version=2025-04-01-preview`,
  header `api-key`, body `{prompt, n, size, quality}`. The PNG comes back under
  **`data[0].b64_json`**; this deployment never returns a URL.
- **Both dimensions must be divisible by 16.** `1080x1350` is rejected outright, so the brand
  size cannot be asked for. `snap_to_16` rounds up to `1088x1360` — exact 4:5 — and Pillow
  scales down to the declared size. No crop, no distortion. Arbitrary `/16` sizes are allowed,
  so this generalises to any declared dimensions.

**Decisions worth knowing before building on this:**
- **`fill(..., escape=False)` for prompts.** HTML-escaping a prompt would send `&amp;` to the
  image model. Markup escapes; prompts do not. Getting this backwards is silent — the image
  would just come out subtly wrong.
- **Dispatch is by capability, not by type.** `render_visual` checks the declaration, then
  checks the supplied renderer has the matching method. Handing it the wrong renderer raises
  rather than silently falling back to the other path.
- **The style reference is concatenated onto every prompt.** It is the only thing holding
  generated imagery to the brand between runs, so it lives on the template, not in the call.
- A refusal (moderation, quota) raises `ImageGenerationError` carrying the service's own
  message and surfaces as 502. A blank image would be the worst possible outcome here.

Learned:
- Pillow 12 moved the resampling constants: `Image.Resampling.LANCZOS`, not `Image.LANCZOS`.
- `Image.open()` returns `ImageFile`, and `.resize()` returns `Image` — reassigning to the
  same name fails mypy. Bind the resized result to a new name.

### US-009 — Directed generation with lineage (done 2026-07-29)

Delivered: `app/models/draft.py` (migration `1bbaa40f8b8c`), `app/generation.py`
(`suggest_templates`, `generate_draft`, `regenerate_text`, `regenerate_visual`),
`app/api_drafts.py`, and a `/studio` page showing the draft, its visual and its lineage.

118 tests green. Verified live end to end: suggestion picked `open-question-then-tested` for
a "we tested 40 listings" idea with a coherent reason; the draft came back in Monte's voice
(lowercase, fragment-heavy) and rendered a brand-exact visual. Lineage recorded as
`(family, version)` for all three templates. `zernio_post_id` stays None — nothing published.

**The defect this slice surfaced, and the rule that came out of it:**
The first live draft filled `left_image_url` / `right_image_url` with prose — "image CTR",
"keyword repetition". Cloudflare rendered the page, the `<img>` tags silently failed, and the
result was a brand-correct image with **two empty boxes and `visual_error: None`**. A
success-shaped wrong answer, which is worse than an error.

- **Slots now declare a `type`.** Only `text`/`number`/untyped are offered to the model, and
  any value it volunteers for another type is discarded (`_written_values`). An unfilled
  `image_url` then raises `MissingSlotValue`, which surfaces as `visual_error` — loud, not
  silent. **Any new visual template with an image slot must set `"type": "image_url"`.**
- There is no asset picker in V1, so image-slot templates cannot complete unattended. The
  live library gained `stat-card`, a text-only brand card, so a draft always gets a visual.

**Other decisions worth knowing:**
- **Lineage keys on `(family, version)`, never a row id.** A test asserts a later edit of the
  hook leaves the draft's recorded version untouched.
- **A failed visual never costs the words.** `_draw_visual` catches everything, records why,
  and leaves the text intact — the prose is the expensive part.
- Exemplars come from the chosen hook's own `provenance`, so a draft is grounded in the posts
  that actually justify the pattern rather than the corpus at large.
- A suggestion naming a template that does not exist falls back to the first approved one
  rather than failing the request.

### US-010 — Publish to Zernio as a draft with lineage in metadata (done 2026-07-29)

Delivered: `app/publishing.py` (`push_draft`, `lineage_metadata`), `create_post` and
`list_posts` on `ZernioClient`, `get_zernio`/`ZernioDep`, `POST /drafts/{id}/push`, and a
"Push to Zernio as draft" action in the studio.

131 tests green, whole gate clean. Verified live on the real account: draft
`6a691c6d95e614b6077edb22` created with `status=draft`, full lineage in its `metadata`, and
`tags=['pixii-intelligence']`. Pushing again returned unchanged and created no second post.

**THE JOIN KEY IS `latePostId`, NOT `_id`. This was the open question and the answer is
counterintuitive — get it wrong and US-011 attributes nothing, silently.**

The create response returns `_id`, and `GET /v1/posts` carries that same value as its `_id`.
But in the analytics payload that value appears as **`latePostId`**; `analytics._id` is a
separate analytics-row identifier. Across all 13 published posts on the account:
`/v1/posts._id` → `analytics.latePostId` matched **13/13**; → `analytics._id` matched **0/13**.

So `Draft.zernio_post_id` (the create-time `_id`) must be joined against
**`analytics.latePostId`**.

**Analytics does not contain unpublished drafts at all.** A pushed draft is invisible to
`/v1/analytics` until it is actually published, so US-011 must treat "pushed but no metrics
yet" as the normal state, not a failure.

Other decisions worth knowing:
- **Draft-ness is asserted two ways**: `isDraft: True` *and* omitting `scheduledFor` /
  `publishNow` / `queuedFromProfile`. Zernio infers draft from the omission; sending the flag
  as well makes the intent explicit rather than implied. Tests assert on both.
- **The idempotency key is derived, not generated** — `uuid5` over the draft id, so a retry
  after a timeout reuses the same `x-request-id` and cannot create a second post. A
  already-pushed draft short-circuits before calling Zernio at all.
- **Every post carries `source: pixii-intelligence` in metadata and a matching tag.** The
  account already held 37 drafts and 13 published posts before this slice; without a marker,
  the app's output would be indistinguishable from Monte's own.
- `GET /v1/posts` returns `metadata`; `GET /v1/analytics` does not. Use `/v1/posts` whenever
  lineage needs reading back from Zernio's side.
